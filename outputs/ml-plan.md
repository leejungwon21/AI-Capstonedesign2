# ML 개발 계획

## 예측할 것
갑작스러운 부재 시점에 각 업무를 얼마나 먼저 인계·확인해야 하는지 High / Medium / Low로 분류한다. 실제 사고 발생 확률을 예측한다고 주장하지 않는다. 완료된 업무는 최신 상태로 구분해 우선순위 대상에서 제외하는 전처리를 둔다.

## 첫 모델과 도구
Python + scikit-learn RandomForestClassifier. 여러 의사결정나무를 학습해 결과를 합치는 지도학습 모델이다. 별도 API 결제 없이 로컬에서 학습한다. Graph ML 자체는 아니며 그래프에서 계산한 수치를 입력으로 사용하는 표형 데이터 모델이다. GNN은 첫 구현 범위에 넣지 않는다.

## 입력
- 업무 상태: 마감까지 시간, 미회신 수, 승인 대기 여부.
- 업무 그래프: 기록상 담당자 수, 부재자와 직접 연결 여부, 명시된 의존 관계에서 영향을 받는 후속 업무 수.
- 정보 상태: 문서·대체 담당자 확인 여부. 존재 여부 미상과 부재를 별도 표현한다.
- 이름, 사례 ID, 출처 URL은 예측 입력으로 사용하지 않는다.

## 데이터와 정답
한 행은 메시지 한 개가 아니라 ‘시나리오·부재 시점·업무’ 한 조합이다. 현재 사례 2개는 개발 예시뿐이다. 서로 다른 마감·승인·대체 가능성·업무 의존 구조를 갖는 독립 시나리오를 확충한다. 개수만 늘리는 대화 복제는 피한다.

팀원이 공통 기준으로 우선순위를 독립 평가하고 불일치를 검토한다. 고정 수식으로 만든 라벨만 학습하면 그 수식 모방 실험이라고 명시한다. 가능하면 업무 경험자에게 평가용 사례를 검토받는다. 사람이 제안한 우선순위는 실제 사고 결과 라벨과 다르다.

## 비교 실험
1. 마감·업무 상태를 이용한 단순 규칙.
2. 업무 상태 피처만 사용한 Random Forest.
3. 업무 상태 + 그래프 피처를 사용한 Random Forest.

Macro-F1, High 재현율, 혼동행렬을 비교한다. 동일 사례에서 파생된 대화·시간대·변형은 같은 그룹에 넣어 학습과 평가에 걸치지 않도록 한다. GroupKFold 또는 독립 시나리오 홀드아웃을 사용한다. 전처리는 학습 데이터에만 맞춘다. 라벨 분포와 사례 수가 부족하면 성능 수치를 제시하지 않는다.

## 설명
실제 마감과 출처를 보여주고, 충분한 평가 데이터가 생기면 permutation importance로 피처의 모델 기여를 확인한다. 이는 인과관계의 증명이 아니다. 데이터가 충분해지기 전에는 학습 완료나 위험도 백분율을 표시하지 않는다.
