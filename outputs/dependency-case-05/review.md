# 사례 ⑤ — 월간 실적 보고서의 후속 업무 의존

사용자가 복사한 DM 8개를 저장했다. 자동 수집·자동 추출·ML 결과가 아니다. 마지막 메시지는 이름이 반복되지 않아 직전 홍길동 발화의 연속으로 해석했으며 source.json에 표시했다. 이 검토 파일과 review.json은 평가용 주석이며 추출 모델 입력에서 제외한다.

## 실험 시점
실제 작성한 대사를 기준으로 이전 대본의 11시·14시 일정을 폐기했다. 날짜와 요일은 미상이다. 이번 실험에서는 표시된 15:43~15:45를 같은 날의 업무 시각으로 간주하고 **16시에 원이정이 갑자기 부재**한다고 가정한다. 이 시각은 분석자가 제안한 설정이며 대화에서 추출한 사실이 아니다.

## 업무 흐름
원이정의 중복 거래 확인·최종 집계 공유 → 홍길동의 숫자·그래프 수정 → 팀장 검토 → 고객사 발송.

| 업무 | 대화상 상태 | 시간 |
|---|---|---|
| 중복 거래 3건 확인·집계 공유 | 진행 중. 수정 전 파일은 사용 금지 | 원이정이 17시까지 공유하겠다고 말함 |
| 보고서 수정 | 틀만 준비됨. 최종 집계 대기 | 홍길동의 예상 소요 1시간 |
| 팀장 검토 | 예정. 완료 보고 없음 | 18시쯤 |
| 고객사 발송 | 완료 보고 없음. 발송 담당자 명시 안 됨 | 보고된 마감 18시 |

## 공백 전에도 존재하는 일정 문제
집계가 17시에 도착하고 수정에 1시간이 걸린다면 18시가 된다. 검토와 발송을 위한 여유가 없으므로 일정 확인이 필요하다. 17시는 약속한 최종 시각이지 실제 도착 시각은 아니며, 검토 시간도 미상이므로 반드시 지연된다고 단정하지 않는다.

## 부재로 추가될 수 있는 문제
집계 담당자의 부재로 최종 파일 공유가 늦어지면 홍길동의 수정과 팀장 검토·발송도 영향을 받을 수 있다. 이미 존재하던 일정 문제 전부를 부재 탓으로 계산하면 안 된다. 지연 시간과 위험 확률은 산출하지 않았다.

## 다음 담당자가 확인할 사항
1. 최종 집계와 중복 거래 확인이 부재 시점까지 어디까지 진행됐는지 확인한다. 수정 전 파일은 그대로 사용하지 않는다.
2. 작업 파일에 접근해 이어서 처리할 수 있는 사람을 확인한다. 홍길동이 집계까지 대체할 수 있다고 단정하지 않는다.
3. 홍길동과 팀장에게 최종 파일 예상 도착 시각·검토 시간을 확인하고 발송 일정 조정 필요 여부를 협의한다.

현재까지 사례 5개는 개발용 재현/가상 사례다. 독립적인 우선순위 정답 검토와 ML 학습·평가는 아직 하지 않았다.
