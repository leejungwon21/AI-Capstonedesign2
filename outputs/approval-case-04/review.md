# 사례 ④ — 발주 요청서

사용자가 DM을 복사해 제공한 7개 메시지를 검토했다. 자동 추출·ML 예측 결과가 아니다. source.json은 원문 자료, scenario.json은 별도 실험 설정이다. 이 검토 문서는 추출 모델 입력에서 제외한다.

실험 설정: 수요일 오전 10시 대화 이후 11시에 홍길동이 갑자기 부재. 제출 마감은 14시이므로 3시간 남음. 실제 게시 시각 15:36~15:38을 업무 시각으로 쓰지 않는다.

| 업무/정보 | 확인된 내용 | 근거 ID |
|---|---|---|
| 요청서 작성·금액·견적서 확인 | 원이정이 완료했다고 보고 | case_04_M001 |
| 최종 승인 | 홍길동에게 요청됨. 대화 당시 승인 전 | case_04_M001, case_04_M002, case_04_M004 |
| 제출 | 최종 승인 후 제출 버튼 사용 가능, 현재 완료 보고 없음 | case_04_M003, case_04_M007 |
| 접수 확인 | 원이정이 제출 이후 확인할 계획 | case_04_M007 |
| 승인자 변경 | 원이정은 직접 변경 불가, 구매팀에 요청해야 한다고 보고 | case_04_M005, case_04_M006 |
| 변경 문의 대상 | 연서영 매니저일 가능성을 언급, 확정 아님 | case_04_M006 |
| 변경 소요 시간 | 확인하겠다는 계획만 있음. 시간 미상 | case_04_M006 |

업무 의존 관계: 최종 승인 → 제출 → 접수 확인. 승인자가 부재하면 후속 제출에 영향을 줄 수 있다. 부재 시점의 실제 승인 여부부터 재확인한다.

미승인이라면 구매팀에 변경 절차·담당자·처리 시간을 확인한다. 연서영을 승인자 또는 확정 담당자로 등록하지 않는다. ‘홍길동만 영구적으로 승인할 수 있음’ 또는 ‘승인자 변경 불가능’이라고 단정하지 않는다.

현재 마감 임박과 승인 의존성 때문에 우선 확인이 필요하다는 것은 검토 의견이며 모델 점수나 실제 사고 결과가 아니다. 우선순위 정답은 별도 평가가 필요하다.
