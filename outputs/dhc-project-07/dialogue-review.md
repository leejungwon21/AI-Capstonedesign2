# 사례 ⑦ 실제 게시 대화 검토

## 사용자 정정 반영
사용자가 M005를 ‘아직 검수완료로 보시면 안 돼요’라는 뜻으로 정정했다. source.json의 body에 정정 문장을 반영하고 original_body에 원문을 남겼다. 따라서 현재 A·B 2026 Q1 상태는 재검수 필요이며, 아래 충돌 설명은 정정 전의 이력이다. Slack 원본 수정 여부는 확인하지 않았다.

사용자 수동 복사 12건. 자동 추출·ML 결과가 아니다. 첫 메시지의 발신자·시각은 붙여넣기에 없어서 발신자는 맥락상 원이정으로 해석하고 시각은 null로 뒀다. 홍길동 계정은 이 사례에서만 이형주 역할이며 실제 계정 이름을 덮어쓰지 않았다.

## 이전 대본과 달라진 부분
- case_07_M006: 이형주 역할이 ‘D는 제가 할게요’라고 수락했다. 부재 전 이미 D 담당 의사가 확인됐다. 실행·완료 또는 정식 권한까지 확인된 것은 아니다.
- D를 아직 아무도 맡지 않은 일로 표시하면 안 된다. D 미착수 사실은 별도 사용자 회고에 있으며, 이번 원문에서는 시작 여부를 명시하지 않았다.
- case_07_M002: 10분 뒤 옐로우 박스에서 설명해 달라는 요청. 실제 만남·설명 완료는 확인되지 않는다.

## 충돌 정보
- case_07_M003: 2026년 1분기는 한 번 더 확인 필요.
- case_07_M005: ‘네네 2026년 1분기는 아직 검수완료로 보시면 돼요.’
- case_07_M012: A·B의 2025년 검수까지 끝난 상태로 봐달라는 말.

M005를 임의로 ‘보시면 안 돼요’로 수정하지 않는다. 2026 Q1 검수 상태는 앞뒤 발언 및 사용자 회고와 충돌하므로 확인 필요로 둔다. 정정이 오면 원문은 유지하고 별도 정정 출처를 추가한다.

## 원문 기준 인계 정보
| 업무 | 상태 |
|---|---|
| A·B, 2025년 | 검수 완료 보고(M003, M012) |
| A·B, 2026 Q1 | 사용자 정정 후 재검수 필요(M003, 정정된 M005, M012) |
| D | 이형주 역할 수행 의사 있음(M006), 완료 보고 없음 |
| C | 이번 검증 제외(M010) |

사용자가 별도로 설명한 ‘이형주가 이후 D를 수행했다’는 결과를 이 원문의 사전 정보로 넣지 않는다. A·B 재검수를 이형주에게 요청했다는 회고 역시 원문과 별도 출처로 유지한다. 이 차이는 실제 경험과 재구성 대본의 차이이며 어느 쪽도 몰래 수정하지 않는다.
